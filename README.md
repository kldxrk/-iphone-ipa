# VNPlayer iOS

SwiftUI 视觉小说播放器。读取「游戏文件夹」（script.vns + 图片 + 音乐），横屏播放。

1.2 起：**支持挂载 KiriKiri 的 .xp3 封包**，界面适配 **iOS 26 的液态玻璃（Liquid Glass）**。

## 已实现

* 脚本引擎（背景 / 立绘 / BGM / 音效 / 选项分支 / 跳转）、打字机文字、自动 / 快进、历史记录、
  8 个存档栏位 + 自动存档（1.2 起连历史记录一起存）、设置（文字速度 / 音量）、游戏库、
  文件 App 导入、内置示例游戏。
* **XP3 容器**：解析索引（含压缩索引、`0x80` continue 标志、krkrz 变体头、exe 内嵌归档），
  按需解出单个文件（段级 zlib），包内素材可直接使用。外部 `script.vns` 优先于包内脚本，方便覆盖调试。
* **内置 XP3 自检示例**：一个素材全部（脚本 / 两张背景 / 立绘 / WAV 音乐与音效）装在 `data.xp3`
  里的小游戏，装好 App 点一下就能验证「索引解析 → 段解压 → 按名查找 → 图片降采样 → 音频物化 → 播放」
  整条链路，不需要先去找一个 KR 封包。由 `tools/make_test_game.py` 生成。
* **液态玻璃**：iOS 26 用系统 `glassEffect` / `GlassEffectContainer` / 玻璃按钮；
  iOS 16~18 平滑降级为超薄材质 + 高光描边（观感接近，没有折射与动态响应）。
* **诊断面板**：不开游戏也能体检——脚本来源、封包文件数、脚本警告、缺失素材清单、
  以及哪些是 iOS 本身解不了的格式。游戏库里每张卡片右侧的听诊器图标就是入口。
* **导入与存储管理**：导入的游戏单独存放在 `ImportedGames/`（和你自己放进 `Games/` 的分开），
  游戏库底部「存储管理」显示各自占用并支持**一键清空导入的数据**；
  任何条目（包括"认不出来"的）都能删除，并会连带清掉该游戏的存档。
* **兼容性报告**（针对"认不出来的游戏"，也就是真实 KR 游戏）：点「体检」会给出
  受保护（加密）条目数、脚本类型与是否明文 KAG、**需要 TJS2 的构造处数**、
  **插件依赖（包内 `.dll`/`.tpm` 数量 + 脚本里提到的 Live2D/motionplayer 等关键字）**、
  素材格式占比、需要转码的素材清单，最后给出可决策的结论：
  能直接玩 / 走 PC 转换器 / 只能走转换器且含人工处理 / 必须引擎级方案 / 无解。
  目的很直接：**先测清楚，再决定往哪条路线投入**（脚本能否读出决定路线 A/B，插件依赖决定路线 C）。
* 图片经 ImageIO 降采样后再进缓存，避免 4K 级 CG 吃光内存。
* 脚本容错：单行写错只记警告，不再整个游戏打不开；UTF-8 / GBK / 带或带 BOM 的 UTF-16 都能识别。

## 未实现（诚实清单）

* **不执行 TJS2 脚本，也没有 KAG3 标签系统**，因此**不能直接运行原版 KiriKiri 游戏**，
  只能跑我们自己的 `script.vns`。要跑原版脚本等于重写一个 KiriKiri 运行时。
* **加密封包解不开**：`info.flags` 的 bit31 只表示「受保护」，密钥不在文件格式里。
  这类条目会被跳过并在诊断里说明。
* **TLG5/TLG6 图片、`.pimg`、`.eri` 解码器**未实现；PAC 封包未实现。
* **Ogg Vorbis 音频放不了**（iOS 的 AVFoundation 不支持，见下），MPEG-1 / WMV 视频同理，都需要先转码。
* 不运行 Windows 的 EXE / DLL。

## iOS 的硬限制（不是本 App 的选择）

| 格式 | 情况 | 建议 |
|---|---|---|
| `.ogg` BGM | AVFoundation 不支持 Ogg Vorbis，且框架不能挂第三方解码器 | 转成 mp3 / m4a / wav |
| `.tlg` 图片 | KiriKiri 私有格式，系统没有解码器 | 转成 png / jpg |
| `.mpg` / `.wmv` 视频 | MPEG-1 / WMV 不在 iOS 支持范围内 | 转成 H.264 的 mp4 |
| 加密封包 | 密钥不在格式里 | 无解 |

构建方式见 BUILD.md，脚本格式见 GAME_FORMAT.md。
